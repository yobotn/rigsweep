## Project

- **What:** RigSweep, a free MIT Windows app that frees RAM, CPU and disk on dev machines cluttered by AI-agent
  sessions, plus its headless CLI / MCP server, a Chrome extension, an anonymous stats API and the website.
- **Standard:** project-engineering-standard v0.1 · **Level:** L2 (real users, anonymous usage stats)
- **Profiles:** CLI (the app's `--disk-report` / `--mcp` mode) + API service (`server/`) + Web app (`docs/`).
  The UI/UX standard also covers the Tauri UI (`ui/`) and the extension (`chrome-extension/`). From the AI
  application profile only the tools/agency and MCP rows apply: RigSweep exposes tools to agents, it calls no LLM.
- **Source of truth:** GitHub (issues, releases, this repo). Decisions in `engineering/decisions/`, accepted
  deviations from the standard in `engineering/exceptions.md`. `docs/` is the public website, not documentation.

## Commands

```bash
npm ci                     # setup (Rust stable + Node 20+ needed; Windows for the app)
npm run dev                # run the app (elevated relaunch: verify UI changes with the release build)
npm run check -- --fast    # JS, translations, site, extension tests (seconds)
npm run check              # everything CI runs: + Rust tests (app, server) + site accessibility
npm run build              # installer: src-tauri/target/release/bundle/nsis/
npm run brand              # local brand studio, http://127.0.0.1:4747 (icons, favicon, social card)
node scripts/prerender-site.js   # after any change to docs/index.html, docs/locales, docs/guides or a version bump
                                 # (also writes the READMEs' story section and docs/guides/feed.xml)
./tools/session-status/session-status.ps1   # before closing a session: committed? pushed?
```

Format: none. **Never run `cargo fmt` in `src-tauri/`**: the code isn't rustfmt-formatted and it rewrites every file.

## Structure

- `src-tauri/`: the app (Rust, Tauri 2). `src/cli.rs` is the headless CLI and MCP server. `catalog/tweaks.json`
  is the reversible tweak catalog.
- `ui/`: the app UI, plain JS, no bundler. `ui/locales/*.js` are the 12 app languages.
- `chrome-extension/`: tab helper, `_locales/*` for its languages.
- `server/`: stats collector + site server (Rust, axum, Postgres). `server/deploy/README.md` is the runbook.
- `docs/`: the website. `docs/<lang>/`, every `index.md` and `docs/guides/feed.xml` are generated by
  `scripts/prerender-site.js`. `docs/guides/` is the blog: articles are written there first, other sites import them.
- READMEs: the "why I built this" section is generated from the site's `story.*` / `stat.*` strings. Edit those.
- `brand/`: brand studio (not deployed). `assets/mark.svg` is the logo, `mark-small.svg` for 32 px and below.
- `scripts/`: checks, screenshots (`scripts/screenshots/make-screenshots.ps1`), deploy, IndexNow.
- `engineering/`: architecture, decisions (ADRs), accepted exceptions, the threat model. `server/deploy/README.md` has the runbooks.

## Hard rules (project-specific, never broken)

1. **Anonymity.** Public things (commits, READMEs, site, release notes, issues, store listings) use only the
   handle `yobotn`. No real name, personal email, Windows username or local paths.
2. **Public language lists show exactly the 11 site languages** (`docs/locales`). The app has one more
   translation (`ui/locales`) that is never listed, counted or flagged publicly: not on the site, READMEs,
   screenshots, structured data, release notes, store listings or posts. Say "11 languages".
   `PUBLIC_LANGS` in `scripts/check-i18n.js` enforces it in CI; ask the maintainer before touching that rule.
3. **Line endings: CRLF in the working tree** (except `*.sh`, LF). Don't add an `.editorconfig` or
   `.gitattributes` rule that rewrites them.
4. **A push to `main` is a production deploy** when it touches `docs/`, `server/` or `deploy.yml`.
5. **Brand:** the family look shared with Focuside and KeepRun. Zinc tile, white mark, one accent `#22c55e`,
   flat. No gradients, no glow, no "AI look", no emoji as the logo. UI icons are Lucide.
6. **Translations are idiomatic**, using each language's official Windows terms, never literal.

## Conventions

- Commits go straight to `main` (solo maintainer, see exceptions). Messages are plain sentences: a short
  subject, then what changed and why. Agent commits end with their `Co-Authored-By` line.
- Every UI string goes through `t()` with a key in `ui/i18n.js` and all 11 other locales, translated.
- Nothing ends, deletes or changes the system without a confirmation dialog, and every change is reversible
  (original values are backed up first, in `%ProgramData%\RigSweep\rigsweep.db`).
- Copy that a user reads follows the README voice: plain verbs, real numbers, no hype.

## Releases

0. Review the changes since the last tag in a fresh agent session (`/security-review`, `/code-review`) and
   verify findings before fixing. Update `engineering/threat-model.md` if a trust boundary changed.
1. Bump the version in `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` (+ `Cargo.lock`), `package.json`
   and `package-lock.json`. Run `cargo test --release` in `src-tauri` (CI compiles tests; `npm run build` doesn't).
2. Write the notes in `.release/notes-<version>.md` (git-ignored). Re-render screenshots if the UI changed,
   then `node scripts/prerender-site.js`, commit, push.
3. `git tag v<version> && git push origin v<version>`, then **right away**
   `gh release create v<version> --notes-file .release/notes-<version>.md --verify-tag`, so `release.yml`
   puts the notes into `latest.json` (the in-app updater) when it attaches the installer.

## Definition of done

Run `npm run check` (or `--fast` for JS/site-only changes) and report the real result. Tests for new behavior.
README (all 11 languages), site, `llms.txt` and in-app About updated when a feature changes what users see.
Never claim success without evidence. Never weaken a test or a check to make it pass without saying so.

## Boundaries

**Always ask before:** pushing to `main` (it deploys), tagging or publishing a release, force-push, deleting
branches/files/data, adding dependencies, changing CI or security settings, anything sent to an external
service (store listings, posts, PRs to other repos, emails).

**Never:** commit secrets (`*.env`, `*.crt` stay in the git-ignored project root); use production credentials
in tests; disable a security check; approve your own work as "reviewed".

## Handoff

If you stop before finishing, leave a handoff in a GitHub issue or the release notes draft: done, remaining,
failing, next step. Never put local paths or personal data in it.
