開発の経緯

📖 RigSweep が生まれた理由

AI の時代、開発用ノート PC で動いているのはもう 1 つのものだけではありません。いつもの 1 日でも、複数のターミナルで Claude Code のセッションをいくつも開き、プロジェクトごとに開発サーバーを立て、ビルドのウォッチャーを動かし、ブラウザーはドキュメントやプレビューでいっぱいです。

セッションのたびにプロセスが増え、その多くはターミナルを閉じた後も動き続けます。タスク マネージャーに並ぶのは node.exe、python.exe、chrome.exe の羅列だけで、どのセッションやプロジェクトのものかはわかりません。

次はディスクです。Rust アプリを 3 つ並行して開発していたところ、各プロジェクトの target フォルダーがそれぞれ約 40 GB に膨らみ、合計で約 120 GB になっていました。すべて Cargo が自動では片付けないビルド成果物です。開発ディスク タブは 1 回のスキャンで 3 つとも見つけました。

どれもウイルスやゴミではありません。AI エージェントと仕事をすれば当たり前に残るものと、開発マシンには要らない Windows のバックグラウンド処理です。既存の「PC 高速化」アプリは、怖くて元に戻せないことをするか、開発の流れをまったく知らないかのどちらかでした。だから、自分が欲しかったツールを作りました。

RigSweep は、マシンを実際に使っているものを可視化し、古いものを一掃し、すべての変更を元に戻せる状態に保ちます。

🌐 Chrome (37 プロセス)6.5 GB
⬢ Node + Claude (14 プロセス)2.5 GB
🧩 実行中の Windows サービス~150
🦀 Rust の target フォルダー (3 プロジェクト)~120 GB
作者の 32 GB ノート PC で、作業日の途中に測定した値です。
機能

✨ できること

「PC 高速化」の小手先ではなく、ターミナルと AI エージェントを使いこなす開発者のために作りました。タスク マネージャー、CPU-Z のようなハードウェア情報ツール、クリーナーをひとつのアプリで。

🧹

開発クリーンアップ

Node、Python、Java、.NET などの孤立した開発サーバーやアイドル状態の開発サーバー、ビルド デーモン、エージェント CLI を、プロセス ツリー、プロジェクト、RAM、ポートとともに表示します。

📊

ブースト レポート

見せかけのパーセンテージではなく、実際の前後の測定値を示します。Markdown でコピーして結果を共有できます。

🌐

Chrome タブ ヘルパー

アイドル状態のタブのスリープ、重複タブや localhost:* などのパターンに一致するタブを閉じる小さな拡張機能です。ネットワーク アクセスはありません。

⚙️

元に戻せる最適化

テレメトリ、Xbox、インデクサー、バックグラウンド アプリ、Edge の再インストール防止などを、リスク レベル付きで最適化します。元の値はバックアップされ、ワンクリックで元に戻せます。

🔍

プロセスとスタートアップ

プロセスごとの CPU、RAM、ディスク使用量、各 svchost.exe 内のサービス、そしてタスク マネージャーには表示されない自動起動のサービスとタスクを表示します。

🌍

11 言語対応

アプリ、インストーラー、Chrome 拡張機能は English、Deutsch、Español、Français、Italiano、Português、Русский、日本語、한국어、简体中文、العربية に対応し、各言語の Windows の公式用語を使っています。

🌡️

温度

CPU と GPU の温度を 5 分間の推移とともに表示し、PC が高温のままのときは警告します。ドライバーも管理者権限も不要です。

🔄

更新は自分で選択

既定ではオフです。好きなときに確認するか、1 日 1 回の自動確認をオンにできます。更新プログラムはクリックしたときだけ、署名されている場合に限りインストールされます。

🧽

ブラウザー クリーンアップ

Chrome、Edge、Brave、Vivaldi、Opera、Firefox のキャッシュを空にします。サインイン情報、Cookie、パスワード、履歴には一切触れません。

💾

開発ディスク

触らなくなったプロジェクトの node_modules、.next、target、.venv を削除し、パッケージ・GPU シェーダー・AI ツールのキャッシュを片付け、エージェントが残した git worktree を取り除き、Windows の残りもの（古い一時ファイル、更新プログラムのダウンロード、クラッシュダンプ）を消して、Docker と WSL の仮想ディスクを縮小します。クリックする前に空きがいくつになるか分かり、自動で作り直されるキャッシュは毎週自動で空にできます。

🖥️

ハードウェア

ディスクの健康状態、速度テスト、CPU・GPU・RAM・バッテリーの詳細を、4 つの別ツールではなく 1 つのタブで確認できます。ドライバーのインストールは不要です。

🎮

GPU と AI

各アプリがグラフィックス カードと NPU で何をしているかを、タスク マネージャーと同じカウンターから表示。実行中の AI ランタイム (Ollama、LM Studio、llama.cpp、ComfyUI、PyTorch)、読み込まれたモデル、使用中のビデオ メモリもわかります。

📡

ネットワーク

アダプターごとの通信量、どのアプリがどの接続やリッスン ポートを使っているか、そしてポート 3000 やロックされたファイル・フォルダーを何が使用中かを調べる検索。

🔎

検索

ドライブごとに何が容量を使っているかをフォルダー単位で確認し、パッケージキャッシュを C: から別のドライブや Dev Drive へ移し、アンインストーラーのないプログラム、ダウンロード内の古い大きなファイル、署名のないスタートアッププログラムを、Microsoft Defender のスキャン付きで確認できます。

🎛️

シンプルとプロ

シンプルではダッシュボードとクリーンアップをわかりやすい言葉で表示。プロではプロセス、ネットワーク、GPU エンジン、生の数値が加わります。不要なモニターをオフにすれば CPU を使いません。

🪟

コンソール ウィンドウ

一瞬だけ開いて消えるコマンド プロンプトのウィンドウ。RigSweep は実行された正確なコマンド、起動元 (タスク スケジューラのタスク、サービス、アプリ)、中で動いたものを記録し、その背後のタスクをバックアップ付きでオフにできます。

🤖

AI エージェント向け

rigsweep --disk-report --json と --disk-clean --safe --dry-run は管理者権限なしで動き、rigsweep --mcp は MCP サーバーです。Claude Code、Cursor、Codex が空き容量を確認し、何が使っているかを見て、自動で作り直されるキャッシュを空にできます。

開発クリーンアップ

🧹 古いセッションを安全に一掃

  • 孤立: ターミナルは閉じたのに動き続けているプロセスです。おなじみのゾンビ localhost:3000 などが該当します。
  • 開いているターミナルのアイドル状態のエージェントは事前に選択されません。ユーザーの入力を待っているだけだからです。
  • エディターの言語サーバーはロックされます (VS Code、Cursor、JetBrains、Visual Studio など)。
  • ポートではなく、必ずプロセス ツリー単位で終了します。終了の直前に各行を再確認するため、2 つのプロジェクトを取り違えることはありません。
  • エージェントが残していった MCP サーバーやヘッドレス ブラウザーも検出します。クリーンアップの数秒後には、回復した RAM がライブ メーターに表示されます。

ウイルス対策

🛡️ Defender に削除されましたか?

RigSweep はオープンソースですが、まだコード署名されていません。サービスを変更するツールは機械学習ヒューリスティックからはマルウェアのように見えるため、Defender が誤って検出することがあります (例: Trojan:Win32/Bearfoos!ml。!ml はヒューリスティックによる推測を意味します)。

インストーラーは自身のフォルダーだけを除外するかどうかを確認し、アンインストーラーはその除外を削除します。SignPath Foundation によるコード署名を予定しています。FAQ の全文を読む →

FAQ

❓ 開発者からのよくある質問

RigSweep は何をするアプリですか?

RigSweep は、AI コーディング エージェントを使う開発者向けの、無料でオープンソースの Windows アプリです。ターミナルを閉じた後も動き続ける開発サーバー、ビルド デーモン、MCP サーバー、エージェント CLI を見つけ、それぞれをプロジェクト、RAM、ポートとともに表示し、選んだものを終了します。古い node_modules やパッケージ キャッシュの削除、ブラウザー キャッシュの消去、元に戻せる Windows の調整も行えます。

ターミナルを閉じた後も動き続ける node.exe プロセスを止めるには?

[開発クリーンアップ] を開きます。ターミナルがなくなったプロセスは孤立プロセスとして表示されてあらかじめ選択され、プロセス ツリー全体、プロジェクト フォルダー、待ち受けポート (応答しない localhost:3000 など) も一緒に示されます。[選択項目を終了] をクリックすると、RigSweep はプロセス ID がまだ同じプログラムのものであることを確認してから、各ツリーを終了します。

どの AI エージェントと開発スタックに対応していますか?

Claude Code、Codex、Gemini CLI、opencode、Aider、Goose と、それらが起動する MCP サーバーやヘッドレス ブラウザーに対応しています。開発スタックは Node、Bun、Deno、Python、Java、Gradle、Maven、.NET、Ruby、PHP、Rust、Go、そして WSL 2 / Docker の VM です。

安全ですか? 変更は元に戻せますか?

確認なしに何かを終了したり削除したりすることはありません。Windows の調整はどれも、変更前に元の値をバックアップし、1 つずつでもまとめてでも復元できます。また、最初の変更の前にシステムの復元ポイントが作成されます。エディターの言語サーバーと Windows の重要なサービスはロックされています。

RigSweep は無料ですか? データを収集しますか?

はい。MIT ライセンスで今後もずっと無料で、アカウントも広告もありません。RigSweep は匿名の利用統計（クリーンアップした内容の種類とサイズ、リソースを多く使う有名アプリ、インストールされているハードウェアメーカーのソフトウェア）を共有するかを一度だけ確認します。回答するまで何も送信されず、実際のレポートは設定で確認でき、オフにすると送信済みのデータも削除されます。パス、プロジェクト名、個人データは一切含まれません。更新の確認は、オンにするか「今すぐ確認」をクリックしない限り行われません。

macOS や Linux でも動きますか?

いいえ。RigSweep は Windows のサービス、タスク スケジューラ、Defender を扱うため、Windows 10 と 11 専用です。ただし、WSL 2 の VM は Windows 側からシャットダウンできます。
